# 指定好友自动回复连续处理审查 · 2026-11-04

修复前新增回归实际失败：`automatic friend reply resumes after cooldown without another incoming message or manual click`。同一好友自动完成第一次回复后，在5秒冷却期立即收到第二条，等待5.6秒；原程序仍只调用一次、只提交一次，新消息一直为received。原代码只提示稍后点击生成，没有自动继续机制。

修复采用每好友最新一条、按原生成间隔等待的策略，计时器归属当前run并链接取消。新消息替换旧等待；计时结束后再次核对连接、配置、好友、状态和额度，再生成。等待不占用生成/发送尝试，也不阻塞其他好友。确认模式不会被静默升级为自动发送，失败和额度用完不自动重试。

上一条提交中时不生成下一条。成功回执后唤醒最新的自动模式received项，未知结果暂停好友并取消待处理。人工接管、暂停、退出、重连和配置变更使旧等待失效。原始未知发送不重试和跨run隔离保持。

新增25项核心检查，包含真实短时间等待回归与可控计时器：最新消息替换、不得提前请求、计数、白名单、关键词、暂停/停止/重连/配置（故意忽略取消）、未知发送、成功回执接续、生成失败不重试、手动点击计时边界、好友之间隔离等。新增8项不可见界面检查覆盖100%/200%字号的回复方式、暂停说明和发送禁用。审核正常确认页面及640DIP/200%暂停页面的离屏图；未打开可见程序或进行实际输入。

待处理页、规则表单和冷却设置说明最新一条策略及取消行为，转人工词/发送额度原因明确，暂停记录不再显示将自动继续。没有购买、安装、激活或导入微信自动化组件，没有读取真实聊天或发送消息；个人微信/QQ指定好友实际兼容和收发仍待验收。
