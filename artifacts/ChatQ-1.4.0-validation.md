## New behavior

- Nine-key uses 65,124 normalized offline Rime/AOSP entries, digit/pinyin ambiguity, a pronunciation filter, prefix consumption, candidate expansion, custom shortcuts and local learning. English frequency data contains 46,717 entries. Cloud data merges licensed Rime/CC-CEDICT and modern terms into 147,028 entries. Sources, exact upstream revisions, transformations, hashes and full licenses are bundled; generated datasets can be rebuilt without a network.
- English composition has explicit candidates, conservative space/punctuation correction, immediate backspace undo, capitalization preservation, original-word selection and explicit personal-word retention. Mixed-case names such as ChatQ are protected. Secure/direct/private editors bypass automatic correction. Normal typing sends no English text to a server.
- Cloud words are opt-in, debounced and cached only in memory. Only the active composing code/layout is sent; private/secure/direct editors are gated. Stale results are discarded and local candidates remain usable on failures. Cloud markers are displayed but never inserted into the editor.
- Voice uses an explicit Android AudioRecord activity and runtime microphone permission, 16kHz mono PCM16 WAV, a 20-second cap, stop/cancel/background cleanup, manual recognition and a separate manual insertion step. The in-memory result is tied to the original editor and consumed once. Recording screens prevent screen capture. The backend validates strict WAV headers, duration and signal energy before a private, unprivileged Whisper container processes audio. No supplier speech key is required. Inference logging is disabled; application code does not retain recordings, transcripts or lookup codes.

Use both `deploy/compose.yaml` and `server/deploy/compose.input.yaml`; the latter selects `chatq-api:input-1.4.0` and the private speech service. Speech uses pinned Whisper.cpp v1.9.5 and the verified 59,707,625-byte base-q5_1 model (SHA-256 `422f1ae452ade6f30a004d7e5c6a43195e4433bc370bf23fac9cc591f01a8898`). CPU/memory/concurrency limits and deployment/rollback instructions are in `server/deploy/INPUT-DEPLOYMENT.md`. No schema migration was needed. Prior APKs and the pre-change source backup remain available.

The physical user handset was not connected. Its microphone, OEM installation restrictions, Bluetooth audio and behavior inside specific chat apps still require hands-on verification. Voice requires a network connection, is capped at 20 seconds and is serialized on the current shared CPU server; no multi-user load test, offline speech or dialect-specific accuracy is claimed. The existing user-requested IP/HTTP entry point and internal preview signing are retained. Use HTTPS before a broader deployment involving private audio.
