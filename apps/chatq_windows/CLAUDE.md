# ChatQ Windows development guide

ChatQ contains a WPF/.NET10 desktop assistant and native C++ TSF Pinyin input. Active platforms are Windows and Android; retain the iOS archive without new builds. Keep free personal-API mode, payments off and no membership gate.

Core owns validation, DPAPI CurrentUser storage, bounded requests, cancellation and configuration revisions. API keys never belong in display strings, logs, platform requests or portable backups. Keep encrypted rollback files. Read old state formats without silent truncation. Portable credential-free backups use PBKDF2-SHA256/AES-GCM, preview before restore and preserve local API profiles. The data library and saved analysis progress use independent encrypted stores and scope checks. Do not overwrite sources or replace unreadable data on cancellation/failure.

The native engine links the mobile Pinyin decoder through Windows portability headers. Do not edit mobile decoder code for a Windows-only repair. Compose through TSF, not global hooks or synthetic Enter/send. Reject password, disabled, URL, numeric and read-only contexts as appropriate. Preserve unfinished typing and adjacent editor text.

The inline reply panel opens explicitly without activating another window. Paste Generate reads clipboard text only on activation; Polish reads only the bounded selected TSF range; Copy writes only the selected result on activation. Never poll the clipboard or read surrounding chats. The hidden worker uses bounded anonymous inherited pipes, not command-line text, prompt files, named endpoints or a background service. Share DPAPI-protected API/persona configuration. Do not persist inline prompts/history. Check the current configuration revision and original context/range/focus before every copy/fill.

Tab and Shift+Tab select enabled actions with a visible focus indicator. Enter/Space confirms the focused action, initially Return. Arrow/page keys read or page results without editing. Keep consumed press/repeat/release ownership until release in the originating context, including after panel close; clear it on focus/context changes. Stop, ordinary typing, text/caret changes, Escape and deactivation invalidate work. Short panels may collapse source preview while preserving status, body and copy/fill actions.

MessageHub has a separate encrypted store and immutable run/account/peer/configuration snapshots. Persist reservations and budgets before submission. Distinguish confirmed/unknown receipts, never retry unknown delivery and reject callbacks from replaced sessions. Defaults are paused/manual; external connectors and actual platform compatibility have separate acceptance gates. Never bundle bridges or credentials.

Regression uses injected synthetic adapters and loopback interfaces. Do not import real messaging automation libraries, connect accounts, inspect private windows, send messages, read chat history or scan process keys. Readiness checks stay non-invasive. Inspect Python package metadata without executing .pth files or sitecustomize. OCR/vision fixtures use supplied synthetic images. Microphones and live capture require separate interactive acceptance; previews and synthetic recognition do not prove receiver identity, draft safety or submission receipts.

ChatImport reads only deliberately selected JSON/CSV/ZIP bytes. WechatDatabase accepts only a selected closed, already-decrypted plaintext snapshot, without WAL/SHM/journal or reparse points. Never execute reference exporters/key DLLs, acquire keys, decrypt live databases, follow manifest paths or scan unrelated folders. Bound files, rows, compressed decoding buffers and execution time. Preserve stable IDs, identify unsupported text/media, require identity selection and show exact redacted outbound coverage/evidence before manual model requests. Imported content is untrusted data, not instructions. Manual exports use protected atomic save.

Run `python tests/run-fixture.py <dotnet-path>` for core and invisible WPF checks with synthetic providers. Do not call a paid API or open visible local programs in regression. Native offline decoder tests use CMake/MSVC x64 and x86. Registered TSF/COM and installer upgrade/removal checks run only in a disposable GitHub Windows VM, never by spoofing CI flags on a user computer. Synthetic keyboard metadata is process-local, without physical input injection or user applications.

Preserve icons, runtime/dictionary licenses and installer notices. Test executables must not ship. Installer/uninstaller preserve other input methods, local data and encrypted backups. Updates use the product HTTPS feed and never install automatically. Verify packaged source/version, architecture, hashes, upgrade preservation and downloads. Code signing, screen-reader support, hardware and actual application compatibility remain separate acceptance gates. Public docs contain product behavior and synthetic checks, not personal testing activity or authorization history.
