## QQ：现有 OneBot11 接口可对接外部 NapCat

聊商已独立实现正向混合 WebSocket、Bearer令牌、本人账号核对、指定好友文本事件和私聊提交回执。NapCat官方文档提供相同连接方式与`send_private_msg`。因此接口具备对接条件；实际客户端兼容、登录和指定好友收发尚未验证。

- [官方项目](https://github.com/NapNeko/NapCatQQ)，本次核对`98d781d19815d1625b24d717ce280ecf0a4f6d0c`、发布版本`v4.18.42`。
- [连接文档](https://napneko.github.io/NapCatQQ-Desktop/docs/connections/)说明正向WS同时接收事件和调用API。WebUI密码与OneBot令牌不同。
- [官方配置结构](https://github.com/NapNeko/NapCatQQ/blob/98d781d19815d1625b24d717ce280ecf0a4f6d0c/packages/napcat-onebot/config/config.ts)中`reportSelfMessage`默认false。聊商的人工接管依赖本人消息事件，需开启并实际验证事件是否上报；仅设置true不等于验证通过。

[配置模板](onebot-forward.example.json)是新增一条本机正向WS的参考片段，不是现有配置的完整替代文件。不要覆盖其他连接、账号或令牌；占位令牌必须由本人替换成独立随机值，聊商填写同一个值。只绑定127.0.0.1，不开放公网。网络层debug=false不代表全局文件日志关闭，须另外核对外部组件的日志设置。

准备流程：本人准备外部桥接并登录 → 新建本机WS正向服务 → 在聊商保存本人QQ号、`ws://127.0.0.1:3001/`和令牌 → 添加一位准确QQ号的测试好友并使用确认模式。先验证本人账号与新消息接收，再由本人确认一次合成测试文本的提交对象/结果，最后单独开启该好友自动模式。未知发送不得重试。

上游有[同为QQ9.9.33-52230的Windows启动失败报告](https://github.com/NapNeko/NapCatQQ/issues/2149)，以及[本人消息上报问题报告](https://github.com/NapNeko/NapCatQQ/issues/2106)。这些是他人报告，不代表本机已经失败；也不能据此保证本机兼容。遇到启动/登录限制应停止，不自动改动或降级现有客户端。

[NapCat许可](https://github.com/NapNeko/NapCatQQ/blob/98d781d19815d1625b24d717ce280ecf0a4f6d0c/LICENSE)包含非商业及授权限制。聊商保持独立OneBot协议客户端，不复制、内置或再分发NapCat代码与账号凭据；对外集成分发前还需核对具体授权。

## 微信：可评估免费的 pyweixin，尚未适配到聊商

[Hello-Mr-Crab/pywechat](https://github.com/Hello-Mr-Crab/pywechat)仓库的`pyweixin`面向微信4.1+，有指定聊天监听、自动回复和发送方法；包名为`pywechat127`，本次审查版本1.9.8、源码提交`203e9b8e70a9da4e29c82761851f0d440680ebe8`，要求Python>=3.10、64位Windows。它提供不依赖wxautox4激活的候选路线，不能把现有付费依赖说成唯一选择。

但[作者的可访问性说明](https://github.com/Hello-Mr-Crab/pywechat/blob/203e9b8e70a9da4e29c82761851f0d440680ebe8/Weixin4.0.md)明确记录账号/UI树可见性限制。仓库说明4.1+不等于本机微信4.2或具体账号已通过验证。界面控件不可见时停止，不修改注册表、破解客户端或绕过限制。

不能直接调用其高层自动回复函数接入聊商。审查`src/pyweixin/WeChatAuto.py`发现：该函数自行设置输入框文本并触发发送，模块设置全局PyAutoGUI FAILSAFE=False；监听方法在指定时段结束后返回汇总，还涉及本地聊天文件夹查找和监听模式设置。这与聊商逐条接收、单独确认、不得覆盖草稿及只处理白名单的新文本的要求不同。

开源适配应独立实现如下边界，再用合成对象验证：仅本人选定的唯一好友窗口、建立基线后接收新文本、确认本人/好友/群私聊类型、保护非空草稿、逐次检查原消息仍有效、单次发送保留未知结果、暂停/退出/锁屏取消、固定错误码与无聊天文件日志。不要把库自带的自动发送闭环直接交给AI。

仓库LICENSE文件展示LGPL2.1文本，而项目元数据分类标记LGPLv3；当前只评估，不复制或分发该库，集成前需核清许可及依赖版本。现有wxautox4适配继续作为可选路线，其[官方文档](https://docs.wxauto.org/docs/install.html)要求Plus激活并列出Python3.9–3.13和微信4.1范围，不能证明4.2兼容。

## 实际接通的验收条件

1. 组件与本机客户端可以正常运行，本人完成登录；不代输验证码或规避系统限制。
2. 报告的本人账号与填写一致，唯一指定好友匹配；账号/好友不明、群聊或其他好友不处理。
3. 仅测试准备好之后的新合成文本；不导入、补发或读取历史，不轮询剪贴板。
4. 默认确认模式先核对对象，再确认一次测试回复；确认消息与本人消息上报正常后才逐好友开自动。
5. 草稿非空、本人接管、断线、锁屏、退出或未知发送均按预期暂停；不重复提交、不自动重新登录。

用户此前选择本机仅编译与隔离回归；2026-11-05随后单独批准上述QQ准备、指定会话新消息接收及一条固定回复。其他平台与回归仍保持原范围，不将接收和单次固定发回验收扩展为收费AI或持续自动回复授权。
