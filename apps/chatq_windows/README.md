## 0.6.2 QQ接收诊断与就绪检查

## 0.5.9 资料库备份与已存分析

资料库新增独立.cqlb密码加密备份，包含主动保存的原文、身份与最近一次主动保存的分析，不包含API、消息助手或普通AI对话。使用PBKDF2-SHA256/600000轮、随机盐与AES-GCM认证；密码8–128字符。每份备份最大16MB加封装，损坏、截断、不同格式或错误密码均不写入本机。可在其他Windows账号凭密码恢复；本轮仅验证独立隔离目录，不冒充跨用户/机器实测。安卓尚不支持该格式，普通.cqb仍不包含资料库。

恢复先解密并预览新增/重复/冲突，再勾选确认合并；相同ID保留本机版本，重复恢复不增加记录。预览后本机变化、容量不足、密码变化或取消都阻止旧预览写入，失败保留原文件；不提供静默替换损坏库。解密、校验和合并预览在后台任务执行，UI可停止。

在已载入的资料上完成分析后，可点击“保存分析到资料”，原文与已选身份必须一致。每份资料保留最近一次主动保存的结果、当时的问题/范围/条数/分段摘要和依据。资料库可“查看已存分析”，显示保存时间和历史范围，不调用模型。报告不能自动作为新问题上下文或接入消息助手；分析中断进度仍仅在当前进程，不跨次自动请求。

修复快速分析的多人化名在查看依据时重新分配、可能与发送预览不一致的问题，改为逐行复用本次化名摘录；截断长消息不切断Unicode表情，并对时间字段的常见手机号/邮箱同样遮挡。完成的分段分析不再显示“可继续”的未完成提示；输错备份密码后改对，成功预览会清除旧红色错误样式。默认导入不自动保存，旧资料库v1继续可读；新写入升级为v2以防旧客户端丢弃已存报告，旧版客户端应升级再使用。

## 0.5.8 本机聊天资料库与长记录分析

聊天分析新增“保存到资料库”和“打开资料库”。用户先确认身份、主动勾选保存原文，再加密保存所选会话；默认导入仍只在内存。资料库使用当前Windows账号DPAPI，单独保存在本机数据目录的chat-library.vault，不加入普通对话、消息助手、云同步或便携备份。最多20份、合计50000条消息/16MB，不自动挤掉已有资料。可按名称搜索、改名、载入和确认删除；载入沿用已选身份但重新要求模型发送同意。每次保存为独立新资料，原始文件保持不变。跨电脑请主动另存JSON/CSV，不能直接复制DPAPI文件给其他Windows账号使用。

“分析方式”可选快速摘录或分段长记录；长记录可选最近500/1000/2000条，实际不足时按实际条数。每段最多200条/24000字符，单条超过1600字符在预览明确缩短；超过20段时在调用前要求减少范围，不静默漏掉消息。每段保留原始全局M编号，逐段预览，最多21次模型请求（包括一次综合）；范围与调用次数在勾选和生成前显示，供应商可能收费。仅用户点击生成后顺序请求，每次上限75秒、任务上限10分钟。

当前任务停止或失败后，已完成分段仅在本次进程内暂存；原文、身份、问题、条数、人设或API变化后不复用。用户再次点击生成才继续，不能自动重试或后台恢复。最终观察只能引用实际交给综合步骤的编号；可点击“查看依据”核对化名原文，也可展开按记录顺序排列的分段摘要。报告可另存TXT，生成的建议不会自动发送。最近2000条之外、长消息省略部分与媒体不在分析范围内；不声称阅读全文。

本轮440项核心、425项不可见WPF、29项适配器合成通过；只用合成资料和本地模型接口。微信连接阶段新增输入框能力检查，无法核对草稿时在就绪前停止并给出固定原因；微信客户端控件不可读及真实自动收发尚未解决，QQ连续AI收发、正式签名、真实软件输入和硬件验收仍待完成。安卓1.29.2保持，iOS仅归档，正式收款关闭。

## 0.5.7 模块复查与压缩文字

微信导出新增标准Zstd压缩帧（含未知内容长度帧）、UTF-8文字BLOB、可选`compress_content`和微信4复合文字类型读取。每条编码最多128KiB，解码目的缓冲固定80001字节，正文最多20000个UTF-16字符；未知二进制、坏帧或空白明确计为未解析，超限不截断、不按占位文本冒充原文。缓冲复用并在归还时清理。只处理用户选择的已解密独立副本，不获取密钥或解密数据库，媒体仍不导出。

跨消息库改为分页读取消息位置、按时间和原始`sort_seq`合并，缺失顺序字段才回退到来源ID。同一秒内不再按ID误倒置；只解码全局选中的消息，遇到坏记录继续分页，尽量补足最新200条可读文字。最多检查50000条，超出时要求缩小日期范围。提示分开显示范围内文字记录、本次检查、读取、压缩还原、未解析和非文本条数；未知时间保持为空。

导入补齐Pro JSON的`chat_id/chat_name/is_self`和复合文字类型，标准字段优先级不再受JSON属性排列影响。聊天ZIP与文件夹均支持`messages/*.csv`，不把manifest/contacts/sessions元数据当作消息。

AI对话、聊天文字、分析TXT、PNG表情和加密备份统一使用原子另存，阻止覆盖当前数据库、既有导入文件与聊商本机数据目录；失败和取消保留旧目标。没有改动用户数据格式、API配置或消息助手的真实连接状态。

本轮覆盖11个页面及相关核心组件：回复/润色/话题、AI对话、人设、API、微信导出、聊天分析、消息助手、记录收藏、表情、数据备份/更新和输入法。检查方式及实机缺口见[模块审查](../../artifacts/ChatQ-Windows-0.5.7-module-review.md)。原生输入法/升级/打包组件在隔离VM验证；本机仅编译、合成SQLite/图像/WAV/接口与不可见WPF，不自动打开真实微信/QQ、不调用收费AI。

## 0.5.6 内置微信数据副本导出

新增独立「微信导出」入口，无需API或Python。用户主动选择**已解密、已完成备份的微信4数据副本**，从会话标签中搜索并选择一个会话，再读取最近200条或全部文字（最多50000条），可按UTC起止日期筛选，结束日期包含当天。支持参考Pro工具使用的`session/session.db`、`message/message_数字.db`与可选`contact/contact.db`结构；只读选定范围，合并各消息库并保持稳定顺序、来源消息ID和原文字。

核对后导出JSON/CSV/TXT，JSON/CSV可重新导入。也可直接「转到聊天分析」，不必先另存文件；仍需主动选择哪位是我、核对化名摘录、勾选允许，再由本人点击自备API分析。数据库导出不调用AI；原文/路径/会话标签只在本次进程内暂存，不进入普通会话、消息助手或便携备份。文件另存为明文，保护原始数据库及既有导入文件。

**适用边界：本版读取用户已准备好的可读数据副本，不自动从运行中的微信获取或解密记录。** 加密库、活动WAL/SHM/日志、写入占用、链接、格式不符或副本变化时停止并提示。不会扫描全盘、提取密钥、运行参考工具、修改微信或读取其他目录。2GB/单库、8GB/总库、128个消息库、2000个会话、35/45秒读取时限；单条文字最多20000字、导出文件最多16MB，超限不静默截断。

当前只导出可读文字。图片、语音等非文本与压缩/二进制文字会显示未导出数量；不伪造媒体内容或未知我方标记。可选发送者映射缺失时保留发送者ID，群聊仅移除识别出的发送者前缀，私人消息中的冒号/换行保持原样。真实微信数据副本与各客户端版本仍待用户验收；开发仅用生成的SQLite样本，不读取真实聊天。

数据库组件随自包含安装包分发；使用官方Microsoft.Data.Sqlite 10.0.14与SQLitePCLRaw 2.1.13，无第三方导出器EXE/密钥模块。连接只读、私有缓存、不池化；持有只读共享保护后使用不可变副本模式，不创建WAL/SHM。取消/时限使用SQLite interrupt；扩展加载默认关闭、禁用可信schema、只允许固定结构表和参数化会话/日期条件。第三方许可随包附带。`--check-export-runtime`是显式、无窗口的RAM诊断，在读取账号数据或启动GUI前退出；隔离构建会验证安装后的单文件程序可加载原生SQLite。

## 0.5.5 聊天读取包导入与文字另存

按本次用户确认的原版「微信聊天导出工具_安装包」对接。静态复核主要组件SHA256与0.5.0审查一致，没有运行、修改或分发参考程序，没有读取真实聊天或数据库。

在「聊天分析」选择文件，或点击「导入读取包文件夹」选择导出的`agent_data`、`messages`、包含`agent_data/messages`的读取包根目录。只读取消息JSON/CSV，不读取manifest路径、联系人或数据库，不递归搜索磁盘；合计最多128个文件、16MB、50000条、100个会话。同ID且内容相同的消息去重；不同消息保留。

导入后点击「导出聊天文字」，选择当前会话的最近200条或全部已导入文字，另存JSON、CSV或TXT。JSON/CSV可以重新导入，保留消息ID、会话名、发送人、我方标记、时间及原始文字；CSV保持前四列「时间,发送人,类型,内容」，补充可回读元数据并转义表格公式。TXT用于阅读。图片、语音等非文本不导出，明确显示实际条数。只导出当前选中会话，不自动写入本机记录库或消息助手。

另存文件包含原始文字和称呼，为明文，须由本人主动选择位置；阻止覆盖原始导入文件。取消或写入失败保留旧目标文件，成功后才原子替换。分析建议TXT仍单独导出，不附带原始聊天。修复导入时删除文字首尾空格及最长CSV转义后无法回读的问题；导出页支持窄窗口、200%字号、滚动内容和固定保存/停止入口，版本显示改为读取程序集。

使用顺序：**参考工具导出 → 聊商导入 → 确认哪位是我 → 核对摘录并允许 → 生成分析**。导入/另存不调用AI；分析仍需本人配置API并主动点击。未内置直接从微信数据库提取记录、真实导出文件验收、全文分段分析或媒体理解；这些不算已完成。回归只使用合成记录和localhost接口。

## 0.5.4 自动运行与连续消息合并

首次完成账号登录、API、人设及指定好友配置后，自动模式按「新消息 → 合并连续内容 → 生成 → 直接提交」运行，正常消息无需逐条确认。指定好友页可一次将当前账号启用的好友设为自动，暂停好友和其他账号不受影响。

默认等待最后一条消息2秒（可设0–15秒），与原同好友生成间隔共同生效。最多将最近两分钟内尚未完成的一组连续新消息中的最近5条按顺序交给模型，仍只向最新消息绑定的原好友提交一次。提交确认后完整保留本组输入到独立上下文。已完成批次、旧连接、其他账号/好友、失败和人工接管前的内容不混入下一组；关键词检查也覆盖因5条上限而未送入模型的较早新消息。

连接与额度页可主动开启「打开聊商时自动开始回复」。开关默认关闭，绑定当前账号/连接、好友规则、人设/API版本和额度设置；下次启动无需再次弹连接确认。变更范围、出现未知发送结果、缺少API或非自动好友时不自动启动。消息页和其他页面的暂停入口都关闭未来自动开始，并同步显示开关状态。没有注册Windows开机服务、自动登录或自动重连；外部连接组件和本人登录仍须可用。

真实接入状态保持分别说明：QQ已完成指定好友的新文本接收及一条固定回复实测，连续AI自动回复尚未进行真实验收。微信4.2标准控件读取未取得消息/输入控件；独立OCR诊断的合成识别和校准预览可运行，但未保存有效区域、未验证真实新消息，尚未接入主应用或具备自动发送。诊断程序不包含在安装包中。不能把本次自动流程开发描述成微信已接通或全天无人值守已验收。

## 0.5.3 指定好友自动回复连续处理修复

修复自动模式在同一好友冷却期内收到新消息后，只保留为待生成且不再继续的问题。间隔结束后自动处理该好友最新一条消息；后续新消息替换旧等待，不重复计费或重复提交。此为最新一条策略，不是多条消息合并理解。确认模式仍需手动生成/确认，不自动升级为自动发送。

上一条提交尚未确认时不请求下一次AI；成功回执到达后继续最新消息。未知发送暂停该好友且不重试。暂停、退出、人工接管、账号/配置切换和新消息会取消或失效旧等待，不跨连接继续、不补发历史。API失败和每日额度用完不自动重试。

待处理页明确显示当前好友是自动还是确认模式；暂停后的等待记录不再提示将自动继续。命中转人工词和发送上限分别提示实际原因。全部回归使用本地模拟接口、合成好友和可控计时器；未安装/激活真实连接组件，真实微信/QQ收发仍未验收。

## 0.5.2 消息助手连接隔离修复

修复暂停后重新连接时，旧连接迟到的成功、失败、断开或消息回调影响新连接的问题。连接启动固定使用本次账号/好友配置快照，仅本次连接成功才能显示就绪；旧回调不能触发当前账号的AI生成，也不能误停正在建立或已经就绪的新连接。连接期间配置变化则拒绝就绪。

修复旧连接中的发送迟到失败，误暂停新连接中同一好友规则的问题。仅发送所属连接、配置和账号/好友目标仍一致时，未知结果才暂停该好友；旧结果保留为历史未确认记录，不重试、不加入新上下文。旧记录已由用户清理时，迟到结果不会导致新连接停止。数据格式不变。

回归使用故意忽略取消、延迟启动和延迟发送的合成连接器；没有真实聊天、外部组件或收费AI调用。仍需用户自备授权连接组件和真实软件验收，不代表已经打通微信/QQ个人账号。

## 0.5.0 聊天导入与分析

新增独立「聊天分析」入口，接收用户主动选择的微信聊天导出文件：

1. 选择 `messages.json`、`messages.csv`，或结构化读取包 `messages/` 目录中的单个JSON；也支持只含消息数据的ZIP。不会运行导出程序、加载密钥DLL、解密/扫描微信数据库或跟随manifest中的磁盘路径。安装包ZIP会被拒绝。
2. 选择一个会话，主动确认「哪位是我」。JSON可选择使用逐条`IsSelf`标记；无标记的CSV须手动选发送人。按最近50/100/200条文本分析，支持1–10条建议；受上下文上限影响时明确展示实际条数和长消息缩短情况。可识别时间的会话按时间排序，否则提示沿用导出顺序。
3. 核对化名摘录、当前API目标和实际发送范围，勾选允许后点击生成。发送人用我/对方代称，并替换已知称呼、手机号与邮箱；不能保证识别所有隐私，须核对预览。AI直连当前自备API，不经聊商平台；导入本身不调用AI。
4. 结果包括聊天总结、附有效消息编号的观察、下一步行动、延续话题和回复卡片。可复制、继续润色或主动导出分析TXT；修改问题后重新分析可聚焦下一步怎么聊。未知引用或不完整结果拒绝采用；切换范围、身份、问题、条数或API会取消/失效旧请求。

导入原文及分析只在当前进程内暂存；不写入本机通用会话、消息助手、云端或备份，也不会自动回复好友。退出需重新导入；0.5.5可主动另存当前会话文字，明文分析TXT仍独立保存，原导出文件不修改。媒体只统计占位、不读取或理解图片/语音。当前不支持长期导入库、全文分段总结、OCR补全或跨设备同步。

兼容依据来自用户提供安装包的静态字段：`ExportPayload.Session/Messages`、`AgentMessage`（Id/ServerId/Talker/Sender/IsSelf/Type/Time/Content）及中文CSV列「时间,发送人,类型,内容」。包内Go模块标识为`github.com/piperTang/chatlog_alpha`，自定义WPF界面为`WxKeyCaptureTest`；本项目未执行或再分发这些组件，未验证其真实导出或当前微信兼容。导入回归仅使用合成的对应格式，真实文件由用户后续验收。

## 0.4.0 消息助手（连接适配预览）

面向用户本人账号的指定好友私聊，提供「生成后确认发送」和逐好友明确启用的「自动回复」。每位好友分别选择 API 与人设、分别保留最近20条已确认提交的上下文。打开软件始终暂停，不自启动连接，也不自动重新连接或补发。

1. 我的 API：保存用户自己的兼容 API；消息助手生成使用非流式完整回答，不把半条回答发给好友。
2. 消息助手 → 连接与额度：QQ填写本人号码、本机 OneBot11 混合 WebSocket 地址 `ws://127.0.0.1:端口/` 和至少16位令牌；微信选择已安装并有权使用 wxautox4 的 Python.exe，填写当前微信显示名称。
3. 指定好友：QQ填写准确好友号码；微信填写唯一好友备注名。接收对象绑定后不可改，换人请另建规则。先用默认确认模式；自动模式需要单独确认。
4. 主动连接：核对本人账号、指定好友、调用额度和自动规则，再处理连接后收到的新文本。连接会调用自备 API，费用由供应商计收。按 UTC 日重置的生成/发送尝试上限默认各20次，同一好友生成间隔默认30秒，失败也占尝试次数。
5. 待处理消息：核对原消息，编辑回复再确认。确认发送与人工接管固定可见；在其他页面仍有运行/暂停入口。新消息使旧回复失效，收到可识别的本人手动消息会暂停对应会话；也可随时人工接管。退出或锁屏暂停。

**外部组件与实际验收限制：**

- QQ 是独立编写的 OneBot11 正向 WebSocket 客户端，只允许本机 `/` 混合接口，鉴权握手不跟随跳转、不用 Cookie/代理，校验登录号；出站纯文本与原好友号码绑定。用户须另行准备有权使用的桥接组件，聊商未附带、安装或启动 NapCat/QQ协议实现。连接组件的授权和客户端限制须另行核对。
- 微信是独立 stdio 适配器，仅在用户点连接后启动自选 Python；wxautox4及其激活/商业授权均不附带或自动安装。需能读取本人昵称、准确绑定好友子窗口并检测输入框为空；能力缺失、窗口不符、有未发送草稿时拒绝发送。不支持的依赖版本可能无法连接或发送，不能将本预览描述成已适配所有微信版本。
- 微信界面自动化无法提供与官方消息 API 相同的身份与原子性保证；显示名/备注名变更、同名联系人、输入框控件变化、窗口关闭/最小化、用户并行操作都需要在实际客户端验收。首次先确认模式，不承诺后台无人值守兼容。
- 当前只处理指定好友的纯文本私聊；群聊、图片/语音代回复、离线补历史及自动重连未开放。未监听的好友不进入模型和本机消息记录。不读取历史 API、不轮询剪贴板、不登录替代机器人身份。
- 转人工词默认包含验证码、转账、付款、密码，原消息或回复命中时留在确认队列。词匹配只是路由规则，不能保证识别所有敏感语义。模型没有工具执行权限。
- 发送前落盘预留。组件确认仅表示提交，不代表对方收到；失败/超时/未知结果暂停该好友，不提供自动重试。旧连接的迟到回执不写入新会话上下文。客户端是否上报本人发送事件影响自动接管检测，手动「人工接管」始终可用。
- 消息与连接令牌使用独立 `messages.vault` 由当前 Windows 账号 DPAPI 加密，原子写入并保留 `.bak`；队列最多80条，待确认/未知记录满时暂停而不静默覆盖。通用 `.cqb` 备份暂不包含此文件、代回复上下文或连接配置；卸载仍保留文件。清空记录保留去重标识与当日额度，不能用重新连接刷新额度。

验证仅用合成好友、临时加密数据、localhost模型与本机假 WebSocket 服务，不导入 wxautox4、不运行真实微信/QQ、不读取真实聊天或发送真实消息。实际平台连接与兼容验收仍按用户安排暂缓；本版本仍未正式签名。

## 使用

运行完整版 Setup，按需选择桌面助手和输入法；系统输入法注册需要管理员确认。安装后打开聊商 → 我的 API → 保存供应商基础地址、密钥和模型。生成、测试连接和获取模型列表都由用户主动触发。

- 帮回复 / 润色 / 找话题、人设 / 关系 / 目标、1–10条回复；生成后主动复制再粘贴。
- AI 对话：本机多轮会话、流式回复、停止、重新生成、搜索、改名、删除和文本导出。
- 人设中心：内置人设、自定义编辑、AI 生成草稿后确认保存。
- Ctrl+Alt+Q 唤出助手（只在应用运行期间注册，冲突时提示）；不自动读取或轮询剪贴板，不自动发送消息。
- Win+空格选择“聊商拼音”；字母输入拼音，空格或1–5选词，Page Up/Down翻页，左右键切换候选；Esc取消、退格编辑、Enter确认原文，Ctrl+空格切换中英；系统输入模式入口显示“中/英”，支持点击切换，切换前保留尚未转换的拼音字母。候选栏 AI 按钮唤出同一个桌面助手并进入“帮回复”，保留之前的会话/润色草稿，API、人设与会话共用本机配置。
- API 密钥及本机会话/草稿使用 Windows DPAPI CurrentUser 加密；损坏时停止覆盖，保留加密备份。数据位于当前账号 LocalAppData/ChatQWindows，不因卸载自动删除。

便携版只运行桌面助手，不会自动注册系统输入法。卸载完整版仅移除本项目的 COM/TSF 注册，不改变其他输入法或删除本机用户数据。
